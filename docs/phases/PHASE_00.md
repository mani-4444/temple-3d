# Phase 00 — Reconnaissance and planning

## Goal
Understand the real repository and finalize a feasible plan without changing application code unnecessarily.

## Tasks
1. Inspect the repository tree, README, package manifests, current branch, Git status and uncommitted changes.
2. Identify the framework, styling, scripts, tests, browser tooling, and any existing 3D implementation.
3. Check installed Claude Code skills only if relevant; don't install unrelated tools.
4. Research official React Three Fiber, Drei and Three.js documentation, plus suitable openly licensed Dravidian temple model candidates if browsing is available.
5. Verify candidate asset license, attribution, download rights and technical suitability.
6. Adapt `docs/ARCHITECTURE.md` and `docs/IMPLEMENTATION_PLAN.md` to actual repo state.
7. Create/update `docs/ASSET_CREDITS.md`, `docs/BUILD_LOG.md`, and `docs/KNOWN_ISSUES.md`.
8. Identify available verification commands and browser test capability.

## Constraints
Do not change application code during reconnaissance. Do not purchase assets, deploy, push or merge. If no suitable model can be verified, document the best lawful next option and proceed with a clearly temporary fallback in later phases.

## Acceptance
- [ ] Repository and Git state documented.
- [ ] Stack and commands confirmed from actual files.
- [ ] Asset candidate and license status recorded or blocker documented.
- [ ] Phase plan and architecture adapted to the project.
- [ ] Build log and known issues initialized.
