# Known issues

Record issues honestly. Do not delete an issue until it has been verified as resolved.

| ID | Issue | Severity | Reproduction / evidence | Status | Next action |
|---|---|---|---|---|---|
| KI-001 | Temple model is an original, procedurally generated, stylised GLB rather than a professionally sculpted or scanned model. Sculpture is suggested by simple forms (capsule figures, pilasters, miniature pavilions); there are no image textures. Openly licensed Sketchfab candidates exist, but downloading them requires a signed-in account. | Medium (visual fidelity) | `curl …/v3/models/1449065e…/download` → HTTP 401 "Authentication credentials were not provided." | Open (accepted fallback) | Optional: the user downloads a CC BY model while signed in and follows README → "Swapping in another model". |
| KI-002 | Numbered 3D markers are not occluded by geometry, so during free orbit a marker can appear in front of a building that hides its landmark. | Low | Markers are DOM overlays (Drei `<Html>`) with no depth test — see `src/scene/Hotspots.tsx`. | Mitigated | While a landmark is focused only its own marker is shown. Real occlusion (raycasts or a depth test) was not added because of per-frame cost. |
| KI-003 | Performance was measured on one machine only: Intel UHD integrated GPU, headless Chrome, 63 FPS (vsync-bound) in the landing shot. No physical phone or tablet, Safari or Firefox was tested; mobile layouts were tested by viewport emulation in Chrome. | Medium (coverage) | `npm run perf`; `npm run smoke` uses Chrome device emulation. | Open | Test on real iOS/Android devices and in Safari/Firefox before a public release. |
| KI-004 | The lazily loaded three.js / R3F / Drei vendor chunk is ~980 kB minified (~260 kB gzip). It is above Vite's default 500 kB warning, so the limit was raised to 1100 kB with a comment in `vite.config.ts`. The landing UI does not wait for it. | Low | `npm run build` output. | Accepted | Revisit if more 3D features are added (e.g. import Drei submodules more selectively). |
| KI-005 | Browser console shows one deprecation warning from a library, not app code: `THREE.Clock: This module has been deprecated` (constructed inside @react-three/fiber 9.8, `dist/events-*.esm.js`). The earlier `PCFSoftShadowMap has been removed` warning was fixed by switching to `PCFShadowMap`. | Low | Seen in headless Chrome console during smoke runs. | Open (upstream) | Will disappear with a future R3F release. |
| KI-006 | The GLB build prints `GLTFExporter: Creating normalized normal attribute from the non-normalized one` (3×). The exporter normalises the normals itself and the output is valid. | Low | `npm run build:model` output. | Accepted | None required. |
| KI-007 | When the landing hero is visible and the model fails to load, the centred error card overlaps the hero copy. It stays legible (opaque card, z-index above) and the retry works. | Low | Smoke `05-model-error.png`. | Accepted | Optional cosmetic tweak. |
